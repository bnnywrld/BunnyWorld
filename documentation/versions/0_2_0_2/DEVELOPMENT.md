# Developing BunnyWorld 0.2.0.2

Use Godot 4.5.1 stable and GL Compatibility. Prepared assets are included; opening project.godot does not require external geographic inputs. Scenario: bunny_world_2000_0_2_0_2; starting-world schema 8, save schema 9. Keep same-version save/load. Do not add migrations unless explicitly requested.

## Offline regeneration

Python generators require numpy, scipy, Pillow, shapely, scikit-image and rasterio. Full source rebuilds also require the user's original bunnyversion.zip, JRC GHSL 2000 raster and the listed Poly Haven source photographs. Large raw downloads, intermediate uncompressed material PNGs and obsolete 0.1-era boundary caches are omitted from the source ZIP; their prepared runtime equivalents are included.

1. `python tools/build_provinces_0202.py /path/to/bunnyversion.zip` decodes actual land definitions and State membership, registers reference State centres using a local thin-plate fit, adapts mismatched areas with local fits, restores small labels where possible and fills only within each accepted State. It rebuilds province JSON, reciprocal adjacency, lookup/atlas PNGs and the Vatican override. State/country records remain authoritative. PNG writes use buffered encoding and atomic replacement. Atlas aliases retained for existing offline builders refer to the current layout.
2. `python tools/prepare_population_022.py /path/to/GHS_POP_E2000_GLOBE_R2023A_4326_30ss_V1_0.tif` aggregates year-2000 resident/dense-settlement grid cells on the new geography. Then run `tools/build_urban_022.py` and `tools/layout_cities_0202.py`. Shares are reconciled within each unchanged State; countryside in a city province belongs to that city group, while remaining provinces share one pool. Street layouts test enlarged visible footprints, land/ownership, landmark grounds and mapped river courses. Do not run the old expand_scenery_0201.py on this data.
3. `python tools/build_surface_0202.py /path/to/downloaded_materials` rebuilds independent physical coverage, Antarctic terrain, signed shoreline coverage, relief and material sources. Use `--relief-only` to rebuild just height/coverage. The original macro colour seed is included and prevents repeated dry-colour accumulation. The unique generated forest master is assets/materials/forest_master_0202.png. Photo names, native sizes and MD5 values are data/material_sources_0202.json. Download each from its public metadata URL; snow_field_aerial uses its `col_4k.jpg`, the other selected assets use `diff_4k.jpg`. Call the API/file URLs with an identifying user-agent. Six photographs: aerial_sand, aerial_grass_rock, rocky_terrain, snow_field_aerial, sparse_grass, brown_mud_dry.
4. Run Godot `--headless --path . --script tools/compile_materials_0202.gd`. This compresses the offline images with complete mipmaps into two eight-layer BWM files. At startup resident_terrain.gd selects one fixed texture array. No camera-triggered decode, geography replacement, mipmap generation or upload is permitted. Runtime settings choose the next startup's library; the current array remains immutable.
5. Run tools/build_waterways_0201.py (updated for rank 0–6), tools/build_water_passage_include_0201.py if passage definitions change, and tools/compile_waterways_0201.gd. Centre lines, subpixel fills and CPU picking share passage definitions. Regenerating river ribbons does not simulate naval access.
6. Run tools/build_boundaries_021.py, then compile each kind in a separate Godot process: `--headless --path . --script tools/compile_boundaries.gd -- land`, then sea, then province. Mesh resources are saved without Godot resource compression; final ZIP compression still reduces them. Do not import/read generated assets concurrently with writes. Fully decode atlas PNGs, import sequentially, and run tests/resource_load_tests.gd before scene checks.

CPU elevation and all displacement shaders use radial scale .016, with height exaggeration 8 and a .0000125 base lift. Keep these consistent with picking, surface anchors and camera clearance. The physical shoreline mask is independent of political IDs; Antarctica has no invented owner.

## Validation/export

Run the current Python patch/urban/rendering/waterways tests and GDScript model, relations, rights, urban population, place catalogue, relief and foundation tests. Run full UI smoke, terrain-cache and travel tests with a working GL renderer. Inspect Tokyo, dry/wet terrain, mountains, Antarctica, provinces, small-window demographics and narrow passage captures. Historical version-locked tests are not current acceptance criteria.

`python tools/build_windows.py --godot /path/to/godot --template /path/to/clean/windows_release_x86_64.exe --embed-pck --output /path/to/BunnyWorld_0_2_0_2.exe` imports then embeds the current pack in a versioned Windows executable. Only use the clean official Godot 4.5.1 export template, never a previously exported game EXE. The helper validates the PE pack section, footer/directory and actual loaded project version/resources. Test the full scene directly from that exact executable using Linux Godot `--main-pack` as well; this does not constitute native Windows execution.

Ship a distinct Windows ZIP/folder/EXE, prepared source ZIP, release notes, build identity, validation notes and SHA-256 checksums. Verify ZIP CRCs and saved-release roundtrip bytes. Runtime budget is approximately 500 MB. Historical documentation is under documentation/versions.
